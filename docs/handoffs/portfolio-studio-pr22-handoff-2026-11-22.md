## 2. What is implemented or corrected in PR #22

**App/editor, content management, and privacy**
- Photo Editor import naming: extension-free Name by default, suffix presets `_crop`, `_edit`, `_fix`, `_small`, or custom; visible Output filetype selector `.webp (rec)`, `.jpg`, `.png`. The selected encoder must match exported bytes, MIME and filename. HEIC **input** remains supported; HEIC export was intentionally omitted for browser compatibility. The original owner did not request *silent* format conversion. Published output is currently constrained to at most 800px long side; legacy configurable quality/size and independent full-size JPEG vs WebP thumbnail remain gaps.
- Preserved historical `DSCF4154_crop.heic` catalog display key separately from its actual `DSCF4154_crop.webp` public derivative, without recoding the private HEIC original.
- Photography Arrangement: Balanced, Color harmony, Thematic groups, Visual contrast, and additional/reverse strategies; manual ordering with lock protection. Engineering/Archive manual up/down ordering; independent content/list scrolling and aligned application header.
- Published photo rename/delete with careful separation of catalog entries, shared public derivatives and private originals. Earlier **P1 code-review findings** were corrected: case-only rename on case-insensitive filesystems could Trash the resulting asset, and symlinked publication *directories* could escape the expected root. Source validation and regression tests now protect these paths. A mislabeled WebP/JPEG/PNG published-image description was also corrected. These are code-review conclusions, **not proof that every native UI action has been physically exercised**.
- Light / Dark / System appearance selection restored with shared Mantine theme persistence; theme-matching tooltips have zero hover/fade delay. Existing `backend/window.ts` already persists normal bounds/maximization; do not recreate it. Actual Mac/Windows GUI appearance and restart persistence still need native acceptance.

**Website and gallery**
- Photography layout has a **maximum of two photographs per row at all widths**. At phone widths `<=720` CSS px, use **one per row by default**, except two **adjacent** portraits where *each* has height:width at least 3:2 (i.e., width/height `<= 2/3`), and always preserve filtered catalog order.
- **Do not discard the older full-width rule:** for every row **except the final two rows**, one photo must span the row or a two-photo pair plus gap must fill it; preserve natural aspect ratios without cropping/stretching to force widths. The last two rows *may* be shorter.
- Early phone-height capping broke this full-width requirement. Corrected row grouping and justified width calculation in `js/photography.js`, added geometric regression assertions in `portfolio-studio/frontend/photography/site-layout.test.ts`, and bumped the gallery-script cache key in `photography.html` at `34a6177e`. Desktop/tablet planner stays capped at two photos and justifies interior rows.
- Photography sticky tag spacing and homepage Engineering locomotive framing were also adjusted. **Do not repeat broad website QA without a relevant website change.**

**Packaged macOS startup/signing**
- Earlier Mac packages passed hosted runners but failed on the physical Mac: mounted DMG `open -n -a` yielded `kLSNoExecutableErr`; a copied bundle produced a DYLD refusal to load Electron Framework under Hardened Runtime due to library-validation / Team-ID incompatibility.
- `forge.config.ts` now retains ad-hoc signing (`identity: "-"`) and Hardened Runtime, but applies `com.apple.security.cs.disable-library-validation=true` **only to the main app** for the private-test signing path. This is an intentional **reduction of main-process library-loading protection**, not Developer ID signing/notarization. Do not broaden the entitlement to Electron Framework/helpers or disable Gatekeeper, SIP, Electron sandbox, or hardened runtime.
- Added strict, fail-closed signing checks on actual Forge and mounted DMG bundles (main executable + Electron Framework), a negative control for missing main-app entitlement / runtime / unintended framework exception, plus a verified-process LaunchServices check. Another earlier P1 smoke-test false-green problem (awk matching its own command line) was fixed and regression-tested.

## 4. Failed macOS GUI test automation — finding and stop decision

A repeated Codex desktop-tool investigation consumed substantial owner and agent time without resolving **window visibility**. The tool failures must not be described as Portfolio Studio regressions:

1. First attempted native Portfolio Studio UI attachment timed out `-10005: timeoutReached` despite successful `open` and a live app process ([Mac report](https://github.com/raisinbran/design/pull/22#issuecomment-7086304787)).
2. Control against an already-running benign **Activity Monitor** failed in Codex CUA with `-32602: unknown or expired node_repl continuation`, even in a new task; no window state/image returned ([first control](https://github.com/raisinbran/design/pull/22#issuecomment-7087108472), [fresh session](https://github.com/raisinbran/design/pull/22#issuecomment-7087830562)). An app appearing in process inventory does not prove an accessible visible GUI window.
3. Independent Swift CoreGraphics enumeration initially could not write a compiler cache at `~/.cache/clang` in the workspace sandbox. This **specific** issue was fixed by using `swift -module-cache-path` and writable scratch under `/private/tmp`; the compiled lookup then found **zero eligible on-screen Activity Monitor windows**, so no guessed window ID / screenshot was taken ([report #7088032215](https://github.com/raisinbran/design/pull/22#issuecomment-7088032215)). Zero matches cannot by itself establish a missing Screen Recording entitlement.
4. One window-only `screencapture -i -W -x -o` invocation crashed immediately with status **134** and `dispatch_source_create returned NULL, invalid parameters passed to dispatch_source_create`, before selector/prompt/image. No permissions were changed ([report #7088298330](https://github.com/raisinbran/design/pull/22#issuecomment-7088298330)). macOS Screen Recording status was never established.

**Controlling decision:** [STOP further Codex GUI harness troubleshooting](https://github.com/raisinbran/design/pull/22#issuecomment-7088321871). Subsequent [correction](https://github.com/raisinbran/design/pull/22#issuecomment-7088482153) supersedes the suggestion that the owner must manually watch/click: **routine desktop GUI QA belongs to a capable agent, not the owner**. The owner may approve necessary permissions, installations/launches and final high-level acceptance, but must not be required to perform repetitive screenshot, navigation and tab-testing steps. Do not keep retrying CUA, REPL continuation, Swift window IDs or shell capture in the same broken environment.

Do **not** assume a paid Claude subscription is available or necessary, or guarantee another agent can circumvent OS permissions. Switching to an **already available and working** independently supported desktop automation environment is an option, **only after** it passes one inexpensive benign-window control. If no such environment exists, report **GUI QA blocked by testing capability** and pause; do not manufacture product failures or create an unbounded subscription/tooling dependency.
