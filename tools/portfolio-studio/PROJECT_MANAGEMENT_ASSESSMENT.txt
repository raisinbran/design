Engineering and Archive management assessment - 2026-10-27

Recommendation
Extend Portfolio Studio into one local portfolio-management application with
separate Photography, Engineering Projects, and Archive Collections editors.
Share the asset browser, thumbnails, ordering controls, settings and previews.
Do not force projects or archive collections into the photography record format.
This is an assessment and proposed design; no project editor or page migration
has been implemented as part of this update.

Current repository findings
Engineering: seven accordion projects, 48 content images, six video elements and
substantial narrative text. Stable section IDs are collapseSignal, collapseFiltran,
collapseBolt, collapseSegal-OutletCovers, collapseSegal-WarmingPad, collapseSombrero
and collapseClipIt. Titles, organizations, dates, contributions, captions and
media are currently authored directly in engineeringdesign.html. Existing image
prominence settings are a separate JavaScript map, not a project-management tool.

Archive: two accordion collections (Art and Industrial Design), with 18 content
images and very little narrative. Content and captions are embedded directly in
creativedesign.html. The stable IDs are collapseArt and collapseID. Its hierarchy
is collection -> item/media, rather than Engineering's project -> narrative/media.

These counts describe content inside details sections, not repeated navigation
branding, footer icons, or background cover images.

Proposed source and publishing architecture
- Add a versioned project/collection catalog as the canonical content source.
  Photography keeps its existing media catalog. Use shared asset records or
  helpers for paths, captions, alternative text, credits, crop and prominence.
- Engineering project fields: stable ID, title, organization/context, dates,
  role, summary, contribution bullets, narrative blocks, tools, cover image,
  ordered image/video/document assets, captions/credits, visibility and order.
- Archive collection fields: stable ID, title, introduction, visibility and order;
  child item fields: title, year, medium/tools, caption, optional description,
  ordered assets and cover. Permit future item-level case studies without forcing
  lengthy project fields onto every artwork or industrial-design rendering.
- Keep generated public HTML static. A deterministic local generator should emit
  the current accordion markup and gallery hooks, preserving existing styling,
  IDs, deep links, media paths, video sources and accessibility semantics.
  Do not require a hosted CMS, accounts, database server or frontend framework.
- Preserve assets in their current folders initially. Reference them rather than
  duplicating every image. Keep original high-resolution files and local editing
  state private; use deliberate publication copies when adding new media.
- Do not automatically apply photography watermarks/crops to CAD diagrams,
  technical drawings, videos or credited collaborator assets. Asset type and
  authorship require separate handling and visible credit fields.

Editor workflow for new Engineering projects
1. Add project -> create a draft with a stable, unique ID.
2. Fill title/context/dates/role/summary and contributions.
3. Add and reorder photos, renders, videos and documents. Pick a cover, adjust
   framing, review captions/alternative text and identify credits.
4. Preview the project in the actual website layout before publishing.
5. Publish the reviewed project locally, validate all links/assets and update the
   page in one transaction. Choose project order separately from media prominence.

Editor workflow for Archive additions
1. Choose Art, Industrial Design, or create another collection.
2. Add an item with title/year/medium, then attach one or more media assets.
3. Reorder items/collections and choose cover/framing; preview the collection.
4. Publish locally using the same validation/transaction mechanism.

Migration and implementation sequence
1. Extract the existing content into catalogs and inventory every media reference.
   Preserve paragraph emphasis, links, captions, video options and section IDs.
   An initial importer can retain legacy content blocks until a reviewed conversion
   to structured narrative fields is complete; never silently flatten rich text.
2. Generate pages and compare before/after DOM, image/video references and rendered
   desktop/mobile layouts. Confirm URL fragments and gallery behavior still work.
3. Add Engineering editing first: the seven mixed-media case studies establish
   the richer editor and generator. Support drafts and undo before adding projects.
4. Add Archive's lighter collection/item editor on the shared asset foundation.
5. Offer explicit duplicate/remove/archive operations with confirmations and local
   backups. Refuse stale saves when another window changed the catalog.
6. Keep backups, source originals and generated previews outside public asset
   directories. Editing/publication stays local; Git publishing is a separate step.

Scope distinction
Integrating both into Studio makes sense. Managing them identically to photographs
does not: project narratives, mixed media, collection hierarchy and credits would
otherwise be lost or awkwardly encoded as photo tags/filenames. Reuse the local
application shell and publishing infrastructure, with purpose-built content forms.
